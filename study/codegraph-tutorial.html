1. CodeGraph 是什么？

简单来说，CodeGraph 是一个给 AI 编程助手用的"代码导航仪"。

想象一下：你让 Claude Code 去理解一个项目，正常情况下它需要不断地 grep、find、cat 各种文件，像无头苍蝇一样到处翻。每次搜索都要消耗 token，既慢又贵。

CodeGraph 做的事情很简单：提前帮你把整个代码库建一个索引（就像书的目录），AI 助手要查什么，直接从索引里找，一次调用就够了。

一句话总结

CodeGraph = 代码知识图谱 + 本地 SQLite 数据库 + MCP 服务器，让 AI 助手秒懂你的项目。

2. 为什么需要它？

没有 CodeGraph 的时候

Claude Code 想回答"用户认证是怎么实现的？"需要这样做：

  1. 用 find 搜索相关文件 → 消耗 token
  2. 用 grep 搜索关键词 → 消耗 token
  3. 用 Read 读取找到的文件 → 消耗更多 token
  4. 可能还要派子 Agent 去探索 → 消耗大量 token

整个过程可能需要 20-80 次工具调用。

有了 CodeGraph 之后

同样的问题：

  1. 调用 codegraph_context → 直接拿到相关代码上下文
  2. 调用 codegraph_explore → 深入了解细节

只需要 2-7 次工具调用，而且不需要读任何文件。

3. 它是怎么工作的？

CodeGraph 的工作流程分四步：

第一步：提取（Extraction） ┌──────────────┐ │ 你的源代码 │ ← tree-sitter 解析成语法树（AST） └──────┬───────┘ ▼ 第二步：存储（Storage） ┌──────────────────────┐ │ SQLite 本地数据库 │ ← 所有符号、关系存入 .codegraph/codegraph.db │ • 函数、类、方法 │ │ • 调用、继承、引用 │ └──────┬───────────────┘ ▼ 第三步：解析（Resolution） ┌──────────────────────┐ │ 关系解析 │ ← 把引用连接到定义（函数调用→函数定义） └──────┬───────────────┘ ▼ 第四步：同步（Sync） ┌──────────────────────┐ │ 自动监听文件变化 │ ← 文件改了，自动更新索引 └──────────────────────┘

通俗解释

  1. 提取：CodeGraph 用 tree-sitter（一个超快的代码解析器）读你的代码，识别出所有的函数、类、方法，以及它们之间的调用关系。
  2. 存储：把提取到的信息存到一个本地 SQLite 数据库里，存在你项目的 .codegraph/ 目录下。
  3. 解析：进一步分析代码关系 —— 比如把函数调用连接到函数定义、把 import 连接到源文件等。
  4. 同步：后台监听你的文件变化，代码改了就自动更新索引，始终保持最新。
关键点

所有数据都在你本地，不会上传到任何服务器。不需要 API Key，不需要联网。

4. 安装和配置

第一步：运行安装器

# 一行命令搞定，交互式安装器会引导你完成所有配置 npx @colbymchenry/codegraph

安装器会自动：

  • 检测你装了哪些 AI 助手（Claude Code、Cursor、Codex CLI、opencode）
  • 把 codegraph 安装到你的 PATH 中
  • 为选中的助手自动配置 MCP 服务器
  • 写入使用说明（如 CLAUDE.md、.cursor/rules/codegraph.mdc）

非交互式安装（CI/脚本用）

# 自动检测所有助手，全局安装 codegraph install --yes # 指定助手 codegraph install --target=cursor,claude --yes # 仅打印配置，不写文件 codegraph install --print-config codex

第二步：初始化你的项目

# 进入你的项目目录 cd your-project # 初始化并建立索引 codegraph init -i

这一步会在你的项目里创建 .codegraph/ 目录，并建立完整的代码知识图谱索引。

第三步：重启你的 AI 助手

重启 Claude Code / Cursor / Codex CLI / opencode，让 MCP 服务器加载。之后 AI 助手就会自动使用 CodeGraph 的工具了。

注意

需要 Node.js 20 或更高版本。运行 node --version 检查。

5. MCP 工具详解

CodeGraph 作为 MCP 服务器运行时，提供以下工具供 AI 助手使用：

工具 用途 使用场景
codegraph_search 按名称搜索符号 找到 UserService 类在哪
codegraph_context 为某个任务构建代码上下文 "帮我理解登录功能的实现"
codegraph_callers 查找谁调用了某个函数 看看谁调用了 login() 方法
codegraph_callees 查找某个函数调用了谁 看看 login() 内部调用了哪些函数
codegraph_impact 分析修改某个符号的影响范围 改了接口会影响哪些文件？
codegraph_node 获取某个符号的详细信息 查看某个函数的完整源码
codegraph_files 获取索引的文件结构 快速了解项目目录
codegraph_status 检查索引健康状态 确认索引是否最新

实际使用示例

当你对 Claude Code 说 "用户认证是怎么实现的？" 时：

# 1. AI 先搜索相关符号 codegraph_search("auth") # 2. 获取认证相关的完整上下文 codegraph_context("how does user authentication work") # 3. 如果需要深入了解某个函数 codegraph_callers("login") codegraph_callees("authenticate")

一次 codegraph_explore 调用就能返回所有相关文件的源码，不需要逐个文件去读。

6. CLI 命令速查

codegraph # 运行交互式安装器 codegraph install # 安装（显式调用） codegraph init [path] # 初始化项目（-i 同时建立索引） codegraph uninit [path] # 从项目中移除 CodeGraph codegraph index [path] # 完整索引（--force 重新索引） codegraph sync [path] # 增量更新索引 codegraph status [path] # 查看索引统计信息 codegraph query <search> # 搜索符号（--kind, --limit, --json） codegraph files [path] # 查看文件结构 codegraph context <task> # 为 AI 构建上下文 codegraph affected [files...] # 查找受影响的测试文件 codegraph serve --mcp # 启动 MCP 服务器

实用技巧：affected 命令

codegraph affected 可以追踪依赖关系，找出哪些测试文件受到源码变更的影响：

# 直接传文件 codegraph affected src/utils.ts src/api.ts # 配合 git diff 使用 git diff --name-only | codegraph affected --stdin # CI 脚本示例：只跑受影响的测试 AFFECTED=$(git diff --name-only HEAD | codegraph affected --stdin --quiet) if [ -n "$AFFECTED" ]; then npx vitest run $AFFECTED fi

8. 框架路由识别

CodeGraph 能识别 Web 框架的路由文件，并建立 URL 和处理函数之间的关联。这意味着问"谁调用了这个接口"，它能直接告诉你对应的 URL 路径。

在 Django 项目中，CodeGraph 能识别 urls.py 里的 path('login/', LoginView.as_view())，并把它和 LoginView 类关联起来。当你问"LoginView 的入口在哪"，它能告诉你 URL 是 /login/。

9. 常见问题

Q: "CodeGraph not initialized" 报错

在项目目录下运行 codegraph init 即可。

Q: 索引很慢怎么办？

检查 node_modules 等大目录是否在排除列表中。可以在 .codegraph/config.json 里配置排除规则：

{ "exclude": [ "node_modules/**", "dist/**", "build/**", "*.min.js" ] }

Q: MCP 服务器连接不上

  • 确认项目已初始化（.codegraph/ 目录存在）
  • 检查 MCP 配置中的路径是否正确
  • 手动测试：codegraph serve --mcp

Q: 后端显示 "wasm" 而不是 "native"

运行 codegraph status 查看。如果显示 Backend: wasm，说明用的是慢速备用引擎。解决方法：

# macOS：安装编译工具 xcode-select --install # 然后重新构建 npm rebuild better-sqlite3

之后 codegraph status 应该显示 Backend: native。

Q: 代码改了但索引没更新？

MCP 服务器会自动监听文件变化（有 2 秒的静默窗口）。如果没更新，手动运行 codegraph sync。

Q: 支持 Windows 吗？

支持。Windows、macOS、Linux 都可以正常使用。

10. 总结

CodeGraph 的核心理念很简单：与其让 AI 每次都从头搜索代码，不如提前建好索引，让 AI 直接查。

适合谁用？

  • 经常用 AI 编程助手（Claude Code / Cursor / Codex CLI / opencode）的开发者
  • 项目文件较多（500+），AI 助手理解项目比较慢的场景
  • 想在 AI 辅助编码上省钱的开发者（减少 35% 的 API 费用）
